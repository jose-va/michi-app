## Aprendizajes y errores a evitar
- Agentes SDD en `mode: all`. Solo `planner` e `implementer` editan `MEMORY.md`; `planner` cambia `Estado:`. Solo `implementer` usa skills libres.
- Leer `node_modules/next/dist/docs/` antes de tocar Next.js. Cierre de spec: cambiar solo `Estado:`.
- Editar con la herramienta de edición, no con Get/Set-Content de PowerShell (daña acentos).
- Probar con variables de entorno rellenas y mirar el log del servidor; no copiar la URL de Maps con clave de `list_network_requests`; restringir la clave a Maps JS API y dominios.
- `resize_page` no baja de ~500 px; usar emulate viewport para 320/375.
- `GET /auth/user` 401 = sesión cerrada: `getProfile()` devuelve `null` en silencio.
- Los tests se desfasan por /features previos: corregir el test sin tocar UI cuando el cambio es intencionado. Specs medibles: doble vuelta QA antes de aprobar.
- Reporter por defecto de `npm test` no imprime totales: usar `npx tsx --test --test-reporter=tap` y leer `# tests/pass/fail`.
- Servicios testeables por inyección (`fetcher`, `baseUrl`) en vez de mock global de `fetch` (patrón `UserService`, `getFeaturedProducts`).
- No sobrescribir colores del `<Calendar>` con `className`: los tres calendarios comparten el tema shadcn (`bg-primary`).
